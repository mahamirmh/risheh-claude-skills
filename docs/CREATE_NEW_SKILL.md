# راهنمای ساخت Skill جدید

## اصول طراحی

یک Skill خوب باید:

- فقط یک مسئولیت روشن داشته باشد.
- نام و فرمان کوتاه و یکتا داشته باشد.
- ورودی مورد نیاز و خروجی مورد انتظار را مشخص کند.
- از حدس، ساخت داده و تغییرات خارج از دامنه جلوگیری کند.
- معیار کیفیت و نکات ایمنی داشته باشد.
- با چند مثال واقعی قابل فهم باشد.

## ساخت پوشه

```text
skills/<skill-name>/SKILL.md
```

مثال:

```text
skills/api-contract/SKILL.md
```

## قالب پیشنهادی

```md
# Skill: api-contract

## فرمان
`/api-contract`

## هدف
هدف دقیق Skill را توضیح بده.

## ورودی‌های مورد انتظار
- ورودی اول
- ورودی دوم

## دستورالعمل
1. مرحله اول
2. مرحله دوم
3. مرحله سوم

## محدودیت‌ها
- داده جعلی نساز.
- خارج از Scope تغییر ایجاد نکن.
- اطلاعات حساس را منتشر نکن.

## قالب خروجی
- بخش اول
- بخش دوم
- معیار پذیرش

## مثال
`/api-contract قرارداد API ثبت سفارش را طراحی کن`
```

## چک‌لیست بازبینی

- آیا Skill فقط یک مسئله مشخص را حل می‌کند؟
- آیا فرمان با Skill دیگری تداخل ندارد؟
- آیا خروجی قابل استفاده و قابل بررسی است؟
- آیا حالت‌های خطا و اطلاعات ناقص مدیریت شده‌اند؟
- آیا موارد امنیتی و محرمانگی پوشش داده شده‌اند؟
- آیا مثال استفاده وجود دارد؟

## نصب پس از افزودن Skill

بعد از Commit و Pull، اسکریپت نصب سیستم‌عامل را دوباره اجرا کنید:

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1
```

### macOS / Linux

```bash
./scripts/install-macos.sh
```
